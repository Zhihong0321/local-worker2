Local Gmap Worker API

Google Maps business scans, web page reads, and LinkedIn profile and company scraping as an API. Jobs run on Windows worker PCs and are posted back here.

Base URL

All paths below are relative to this service:

https://YOUR-SERVICE

Health is open. Every other route needs your API key.

Auth

Send your API key on every request except /health and /docs:

Authorization: Bearer <API_KEY>

x-api-key: <API_KEY> works too. A missing or wrong key returns 401.

Start a scan

POST/api/scan

curl -X POST https://YOUR-SERVICE/api/scan \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"keyword":"factory","place":"Taman Daya","max":200,"wait":600}'
FieldMeaning
keywordBusiness type. business, factory or shop with a place sweeps that family's words. Any other keyword is one plain search, up to 300 results.
placeArea, e.g. Taman Daya. At least one of keyword or place is required.
maxResults to return, 1 to 500. Default 200.
waitSeconds to hold the request open for the result, up to 900. Without it you get 202 at once.
timeoutMsScan deadline, 120000 to 1800000. Default 600000. At the deadline the worker posts what it has.
searchMode"location_only" searches the place alone.
workerPin the scan to one worker by name.

200 with { "job": ... } when the scan finished within wait. 202 with the job while it is still running. 400 for invalid input, with an error message.

Scrape a LinkedIn profile or company

POST/api/linkedin

Read one person profile or company page using the worker's authenticated LinkedIn session and linkedin-scraper. A person result may include name, location, about, experience, education, interests, accomplishments and contact details. A company result may include name, about, website, phone, headquarters, industry, size and specialties. Available fields depend on the page and the signed-in account's access.

This endpoint takes a known URL. It does not expose LinkedIn search, job listings, company posts or bulk scraping.

curl -X POST https://YOUR-SERVICE/api/linkedin \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"kind":"person","url":"https://www.linkedin.com/in/example/","wait":60}'

For a company, send {"kind":"company","url":"https://www.linkedin.com/company/example/"}.

FieldMeaning
kindRequired: person or company.
urlRequired HTTPS URL on linkedin.com or www.linkedin.com. Use /in/... for a person and /company/... for a company; omit query strings and fragments.
waitSeconds to wait for completion, up to 900. Default 0 returns the queued job immediately.
timeoutMsWorker execution limit, 10000 to 300000 milliseconds. Default 120000.
workerOptional worker name to pin the job to a particular PC.

The response is { "job": ... }: HTTP 202 while pending or running, or 200 if finished during the wait. Invalid input returns 400. A completed request can still have job.status: "failed"; check job.error.

When successful, job.result has this shape (the contents of data vary by page):

{
  "kind": "person",
  "url": "https://www.linkedin.com/in/example/",
  "data": { "name": "Example", "location": "...", "experiences": [], "educations": [] },
  "provider": "linkedin-scraper",
  "tookMs": 12345,
  "worker": "pc-example"
}
# Poll a queued job (replace <id> with job.id)
curl -H "Authorization: Bearer $API_KEY" "https://YOUR-SERVICE/api/linkedin/<id>?wait=60"

# Cancel a pending or running job
curl -X DELETE -H "Authorization: Bearer $API_KEY" "https://YOUR-SERVICE/api/linkedin/<id>"

A worker must be configured with the scraper, Chromium and a local authenticated LinkedIn session. See the repository README for setup. Sessions can expire, and LinkedIn restrictions or page changes can cause incomplete results or failures. A pending LinkedIn job times out after the queue timeout (30 minutes by default) if no suitable worker claims it.

Company data comes from one About page. If no details can be read, the job fails with about_not_read instead of returning only a name. A missing page reports not_found; an expired login or checkpoint reports session_expired; a rate limit reports rate_limited. Individual fields may still be empty when absent from the page. Successful results include waitedMs for worker pacing, navigationMs for page navigation and tookMs for scraping. A failed job includes its pacing wait in the error text.

Workers space LinkedIn job starts by 60 seconds by default; this does not guarantee that LinkedIn will not restrict an account, especially across multiple workers. A rate-limited worker rests LinkedIn jobs for 30 minutes; an expired session stops LinkedIn claims until sign-in is renewed. Maps and fetch jobs remain available. GET /api/workers shows linkedinCoolUntil, linkedinSessionExpired, and the current coolReason.

Fetch a page

POST/api/fetch

Reads one web page on a worker PC and returns it as markdown, text or HTML: a local stand-in for Jina Reader or Tavily extract. The call answers with the page by default.

curl -X POST https://YOUR-SERVICE/api/fetch \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com/article"}'
FieldMeaning
urlThe page, http or https. Required. Workers refuse private and local addresses, including redirects to them.
formatmarkdown (default), text or html.
mainContentDefault true: the page's <main> or <article> when it holds most of the text, without nav, header, footer, scripts or hidden elements. false returns the whole page.
waitSeconds to hold the request. Default: the fetch's timeout plus 30 s. 0 returns 202 with the job at once.
timeoutMs10000 to 300000. Default 60000. A fetch no worker claims within this fails.
workerPin the fetch to one worker by name.

The job's result:

{ "url": "...", "finalUrl": "...",   // finalUrl after redirects
  "status": 200, "contentType": "text/html", "title": "...",
  "format": "markdown", "content": "# ...", "length": 14832,
  "truncated": false,                // true past 5 MB of page, or PDF pages left out
  "provider": "scrapling-local", "tookMs": 1079, "worker": "pc-..." }

PDFs come back as markdown, tables as markdown tables (format: "text" gives plain text). A PDF reads at about 0.4 s a page: past the fetch's deadline it returns the pages it has with truncated: true, so send a larger timeoutMs for very long ones. Limits: 30 MB and 300 pages. Scanned PDFs without a text layer come back nearly empty.

A site answering HTTP 400 or above, another kind of file (image, Word) or a refused address fails the job with an error. Plain text and JSON come back as they are. Pages are read without a browser, so content drawn only by JavaScript is not there.

Get, cancel and list jobs

GET/api/scan/{id}?wait=60

/api/fetch/{id} and /api/linkedin/{id} also retrieve jobs.

Returns the job. wait holds the request until it finishes, up to 900 seconds. 404 for an unknown id.

DELETE/api/scan/{id}

Cancels the job. /api/fetch/{id} and /api/linkedin/{id} also accept DELETE. 409 if it has already finished.

GET/api/scans?status=running

Recent jobs, up to 200, without results. status is optional: pending, running, done or failed. type is optional: gmap.scan, web.fetch or linkedin.scrape.

Job object

{
  "id": "857ccca76cfe",
  "type": "gmap.scan",       // gmap.scan | web.fetch | linkedin.scrape
  "status": "done",          // pending | running | done | failed
  "worker": "pc-desktop-camhl16",
  "attempts": 1,
  "createdAt": "...", "startedAt": "...", "finishedAt": "...",
  "payload": { "keyword": "cafe", "place": "Taman Daya", "max": 5 },
  "result": {
    "query": "cafe in Taman Daya",
    "found": 5,
    "capped": true,            // true: there were at least max results
    "businesses": [
      { "name": "...", "rating": 4.9, "reviews": 3243, "category": "Restaurant",
        "address": "...", "phone": "...", "website": "...",
        "mapsUrl": "...", "place_id": "..." }
    ],
    "googleRequests": 1,
    "stoppedEarly": null,      // set when Google refused the worker's line
    "tookMs": 2337,
    "worker": "pc-desktop-camhl16"
  },
  "error": null                // set when status is failed
}

result is set once the job is done. error is set if it failed.

Behaviour

  • No worker free. A job waits in the queue. A scan fails after 30 minutes with no worker, a fetch after its timeoutMs.
  • Lost worker. A job whose worker stops responding goes back to the queue. After 3 lost workers it fails.
  • Google refusal. The worker posts what it has and rests for 30 minutes. The service sends it no scans meanwhile; it still takes fetches.
  • Restart. The queue is held in memory. A redeploy drops pending jobs. A job already running is re-filed when its worker posts the result.

Example: a complete round trip

# 1. start the scan, waiting up to 10 minutes
curl -X POST https://YOUR-SERVICE/api/scan \
  -H "Authorization: Bearer $API_KEY" -H "Content-Type: application/json" \
  -d '{"keyword":"factory","place":"Taman Daya","max":200,"wait":600}'

# 2. if the answer was 202, poll until it finishes
curl -H "Authorization: Bearer $API_KEY" \
  "https://YOUR-SERVICE/api/scan/<id>?wait=60"
