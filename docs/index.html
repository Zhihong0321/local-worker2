Local Gmap Worker API

Google Maps business scans, web page reads, page screenshots, SEO and GEO website audits, and web ChatGPT queries as an API. Jobs run on worker PCs and are posted back here.

Base URL

All paths below are relative to this service:

https://YOUR-SERVICE

Health is open. Every other route needs your API key.

Auth

Send your API key on every request except /health and /docs:

Authorization: Bearer <API_KEY>

x-api-key: <API_KEY> works too. A missing or wrong key returns 401.

Required job identification

Every job-creating POST (/api/scan, /api/fetch, /api/shot, /api/audit, /api/lookup, /api/chat, and /api/ads) requires callerId and taskDescription strings. Set callerId to the origin URL, IP address, or device name. Set taskDescription to 1–50 characters. These values are supplied by the caller and are not independently verified. They appear in the job and GET /api/scans. Missing or invalid values return 400; existing clients must be updated.

DELETE /api/jobs clears all pending and running jobs, returning { cleared, jobIds }. Finished jobs remain in history. A running worker may continue its work, but its late result is rejected.

Start a scan

POST/api/scan

curl -X POST https://YOUR-SERVICE/api/scan \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"callerId":"office-pc","taskDescription":"API request","keyword":"factory","place":"Taman Daya","max":200,"wait":600}'
FieldMeaning
keywordBusiness type. business, factory or shop with a place sweeps that family's words. Any other keyword is one plain search, up to 300 results.
placeArea, e.g. Taman Daya. At least one of keyword or place is required.
maxResults to return, 1 to 500. Default 200.
waitSeconds to hold the request open for the result, up to 900. Without it you get 202 at once.
timeoutMsScan deadline, 120000 to 1800000. Default 600000. At the deadline the worker posts what it has.
searchMode"location_only" searches the place alone.
workerPin the scan to one worker by name.

200 with { "job": ... } when the scan finished within wait. 202 with the job while it is still running. 400 for invalid input, with an error message.

Fetch a page

POST/api/fetch

Reads one web page on a worker PC and returns it as markdown, text or HTML: a local stand-in for Jina Reader or Tavily extract. The call answers with the page by default.

curl -X POST https://YOUR-SERVICE/api/fetch \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"callerId":"office-pc","taskDescription":"API request","url":"https://example.com/article"}'
FieldMeaning
urlThe page, http or https. Required. Workers refuse private and local addresses, including redirects to them.
formatmarkdown (default), text or html.
mainContentDefault true: the page's <main> or <article> when it holds most of the text, without nav, header, footer, scripts or hidden elements. false returns the whole page.
waitSeconds to hold the request. Default: the fetch's timeout plus 30 s. 0 returns 202 with the job at once.
timeoutMs10000 to 300000. Default 60000. A fetch no worker claims within this fails.
workerPin the fetch to one worker by name.
keepErrorsDefault false. true: a page that answers 4xx or 5xx comes back as a done job with its status and body, instead of failing. Network errors (DNS, refused, TLS) still fail.
headersDefault false. true: the result adds headers and redirects (below).

The job's result:

{ "url": "...", "finalUrl": "...",   // finalUrl after redirects
  "status": 200, "contentType": "text/html", "title": "...",
  "format": "markdown", "content": "# ...", "length": 14832,
  "truncated": false,                // true past 5 MB of page, or PDF pages left out
  "provider": "scrapling-local", "tookMs": 1079, "worker": "pc-..." }

// with "headers": true, also:
  "headers": { "server": "nginx", "content-type": "text/html; charset=UTF-8", ... },
  "redirects": [ { "url": "http://example.com/", "status": 301, "location": "https://example.com/" } ]

headers are the final response's, names in lower case; a repeated header is joined with ", " (set-cookie with a newline). redirects has one entry per hop, in order, with location made absolute; it is empty when the page did not redirect.

PDFs come back as markdown, tables as markdown tables (format: "text" gives plain text). A PDF reads at about 0.4 s a page: past the fetch's deadline it returns the pages it has with truncated: true, so send a larger timeoutMs for very long ones. Limits: 30 MB and 300 pages. Scanned PDFs without a text layer come back nearly empty.

Without keepErrors, a site answering HTTP 400 or above fails the job ("the site answered HTTP 404"). With it, an error page comes back as markdown, text or HTML like any page, as its text if it is another type, and as an empty content if it has no body. Another kind of file (image, Word) or a refused address fails the job with an error. Plain text and JSON come back as they are. Pages are read without a browser, so content drawn only by JavaScript is not there.

Screenshot a page

POST/api/shot

Opens one page in a headless browser on a worker PC and returns a JPEG of what a visitor sees: a proof screenshot, with an optional text outlined in red. Windows workers use the Microsoft Edge Windows already has, Mac workers Google Chrome; nothing is downloaded. Only workers with that browser take shots (job type web.shot, opt-in like site.audit), and only workers on the current version: a Windows PC needs the package downloaded again (GET /api/worker/package), a Mac a git pull. GET /api/workers shows which workers list web.shot in their types. The call answers with the shot by default.

curl -X POST https://YOUR-SERVICE/api/shot \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"callerId":"office-pc","taskDescription":"API request","url":"https://example.com/contact","device":"mobile","find":"Call us"}'
FieldMeaning
urlThe page, http or https. Required. Workers refuse private and local addresses, for the page, its redirects and everything the page loads.
devicedesktop (default): 1280 × 760, scale 1. mobile: 390 × 780, scale 2, touch, a phone's user agent.
findOptional text, up to 500 characters. The first visible element whose text contains it (case and runs of spaces ignored, first 60 characters) gets a 4px #e11d48 outline offset 4px and a rgba(225,29,72,0.10) background, and is scrolled to the centre of the screen. The shot is taken 1.5 s later, so text that fades in on scroll has appeared.
waitMsWait after the page's load event before the shot. 0 to 30000, default 1500.
qualityJPEG quality, 1 to 100. Default 72.
waitSeconds to hold the request. Default: the shot's timeout plus 30 s. 0 returns 202 with the job at once.
timeoutMs10000 to 300000. Default 60000. A shot no worker claims within this fails.
workerPin the shot to one worker by name.

The job's result:

{ "url": "...", "finalUrl": "...", "status": 200, "device": "mobile",
  "title": "...",
  "found": true,            // false: the text was not visible; the shot is the top of the page
  "blocked": false,         // true: the page was a bot check; no image, evidence in "detail"
  "detail": null,
  "image": "<base64 JPEG>",  // the viewport; a mobile shot is 780 x 1560 pixels (scale 2)
  "width": 390, "height": 780,
  "loaded": true,           // false: the load event never came; the shot is what had drawn
  "redirects": [ { "url": "...", "status": 301, "location": "..." } ],
  "documents": [ { "url": "...", "status": 200 } ],  // every page the tab was sent, in order
  "worker": "pc-...", "tookMs": 4200 }
  • Error pages are shot. A page that answers 4xx or 5xx comes back with its status and an image: the error page is the proof.
  • Bot checks are never answered. A Cloudflare challenge (cf-mitigated header, "Just a moment..."), Reddit's JS challenge, an Imperva incident page, DataDome, PerimeterX, Akamai's "Access Denied", Google's "unusual traffic" page, and Turnstile, reCAPTCHA, hCaptcha or Imperva's script on a page with little else, gives blocked: true, no image, and the evidence: 
    "detail": { "evidence": ["header cf-mitigated: challenge", "title "Just a moment...""],
  "title": "Just a moment...", "url": "...", "status": 403, "server": "cloudflare", "text": "..." }
    The browser stops at the challenge page; it is never left to run and clear itself. A long page that only carries a captcha in a form, or a bot-protection script, is shot as normal.
  • What is challenged depends on the browser, not only the site. Checked from a worker PC on 2026-11-07: a commonlii.org search page is challenged (blocked: true), while mia.org.my and bursamalaysia.com answer a real browser with the page.
  • Failures. A page that does not load at all (DNS, refused, TLS), a private address, or a browser that will not start fails the job with an error. With no web.shot worker online, the job fails at timeoutMs.
  • The hub keeps the last 100 finished shots; fetch the image when the job finishes.

Audit a website

POST/api/audit

Queue a site.audit job for an SEO and GEO (generative AI optimization) benchmark report. The worker reads the site on its own internet connection and builds the report; the service stores and returns that result unchanged. Use the caller API key.

curl -X POST https://YOUR-SERVICE/api/audit \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"callerId":"office-pc","taskDescription":"API request","url":"https://example.com/","maxPages":5,"botTest":true}'
FieldMeaning
urlRequired http or https URL, at most 2048 characters. Normalized before queuing.
maxPagesWhole number from 1 to 25, default 5. Pages to crawl besides the home page.
botTestBoolean, default true. The worker refetches the page using AI-bot User-Agents.
workerOptional worker name to pin the audit to one worker.
timeoutMs30000 to 600000 milliseconds, default 180000. A pending audit also fails if nobody claims it within this time. The running lease includes 30 seconds of grace.
waitSeconds to hold the request, up to 900, in the body or query. Default: the timeout plus 30 seconds. 0 returns the job id at once.

Returns { "job": ... }: HTTP 200 if the audit finishes during the wait, otherwise 202 while pending or running. Invalid input returns 400. A finished job may have status: "failed"; check job.error. Poll with GET /api/jobs/{id}?wait=60.

The worker's report is held in job.result, including scores with seo, geo and groups, a checks array, pages and tookMs. Illustrative result:

{
  "url": "https://example.com/", "finalUrl": "https://example.com/", "status": 200,
  "scores": { "seo": 89, "geo": 49,
    "groups": { "crawl": { "score": 100, "area": "seo", "checks": 13 }, "trust": { "score": 6, "area": "geo", "checks": 4 } } },
  "checks": [
    { "id": "trust.dates", "group": "trust", "title": "Publication and Modification Dates",
      "status": "fail", "score": 0, "weight": 2, "pages": 3, "worstUrl": "https://example.com/",
      "detail": "0 of 3 pages pass. Weakest: https://example.com/: No publication or modification dates found.",
      "data": {} }
  ],
  "pages": [{ "url": "https://example.com/", "depth": 0, "title": "Example", "words": 1234,
              "description": "...", "headings": ["h1 ..."], "content": "markdown of the main text",
              "issues": [{ "id": "trust.dates", "status": "fail", "detail": "..." }],
              "scores": { "seo": 90, "geo": 56, "groups": {} } }],
  "facts": { "robotsTxt": 200, "llmsTxt": 200, "certDaysLeft": 62, "bots": [] },
  "notChecked": ["Backlinks and domain authority: needs a paid web-wide link index.", "..."],
  "errors": [], "provider": "local-audit", "tookMs": 45641, "worker": "pc-..."
}

Each check has id, group, title, status (pass, warn, fail or na), score, weight, detail and data.

Workers only receive audits when they explicitly include site.audit in their types poll parameter. The default remains gmap.scan,web.fetch.

What the audit measures

Two scores from 0 to 100, like PageSpeed. SEO is how well Google can crawl, read and trust the site. GEO (generative engine optimization) is how well AI answer engines such as ChatGPT, Claude, Perplexity, Gemini and Google AI Overviews can reach the site, understand it and quote it.

What the worker reads. The page you send and up to maxPages more pages on the same site (links from that page first, then the sitemap). It also reads robots.txt, /llms.txt, the sitemap (the first child of a sitemap index), a made-up URL to test the 404 page, the http:// and www versions of the address, and the TLS certificate. It sends a HEAD request to up to 25 internal links it did not open, and to up to 8 scripts for their size. With botTest it reads the page again as GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, Claude-User, PerplexityBot and CCBot. Last, it looks the site up in Wikidata and the Common Crawl index. That is a few dozen requests, a quarter of a second apart, on the worker's own connection. Pages are read without a browser, the way most AI crawlers read them.

How a score is built. Each check gives a score from 0 to 1 (pass is 1, fail is 0, warn is in between) and has a weight from 1 to 3. na checks, which could not be measured, are left out. A group's score is the weighted mean of its checks, times 100. The SEO and GEO scores are the weighted mean of their groups, using the shares below; a group with no measured checks is left out and the other shares are scaled up. Page checks run on every page read and are averaged, so their detail says, for example, "2 of 3 pages pass" and names the weakest page. Site checks run once.

  • Backlinks and domain authority: these need a paid index of links across the web.

  • Core Web Vitals from real visitors, and a full browser render (Lighthouse).

For fixes written for the site itself, ask for AI advice on the finished audit.

AI advice on an audit

POST/api/audit/{id}/advice

Asks an AI model to read the audited pages and suggest concrete fixes: rewrites that quote the page, questions buyers ask that the page does not answer, and the five actions that matter most for the site. The cloud agy hub (Gemini Flash, sandboxed) answers first; a backup OpenAI-compatible model (DeepSeek by default) answers when agy fails. A suggestion whose quote is not on the page is dropped. Scores never come from the AI.

curl -X POST https://YOUR-SERVICE/api/audit/JOB_ID/advice   -H "Authorization: Bearer $API_KEY" -d '{"callerId":"office-pc","taskDescription":"API request","wait":60}'

Runs once per audit and takes a minute or two. The call waits 20 seconds by default (wait, up to 240) and answers 202 while it runs; GET /api/audit/{id}/advice?wait=60 picks it up, and the job itself carries it as job.advice. 404 for an unknown audit, 409 before the audit is done, 503 when the service has no model set up (AGY_URL/AGY_TOKEN or ADVICE_BACKUP_URL/ADVICE_BACKUP_KEY). A failed run is started again on the next POST.

Site lookup

POST/api/lookup

Run a library handler for a company name on a worker PC's internet connection. The handler's return value is preserved under job.result.result. The call waits for the answer by default.

curl -X POST https://YOUR-SERVICE/api/lookup \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"callerId":"office-pc","taskDescription":"API request","handler":"MY-cims.cidb.gov.my/w1","keyword":"Gamuda"}'
FieldMeaning
handlerRequired library id from GET /api/handlers. Only tiers 1 and 2 can run.
keywordRequired company name, 1 to 200 characters after trimming.
waitSeconds to hold the request, up to 900. Default: the timeout plus 30 seconds. 0 returns 202 with the job at once.
timeoutMsInteger from 10000 to 300000, default 150000. The worker has this long to run the handler. An ordinary lookup also fails if no worker claims it within this time in the queue.
workerOptional worker name to pin the lookup to one PC.

Returns { "job": ... }: HTTP 200 when finished during the wait, otherwise 202. Illustrative successful answer (records vary by handler):

{
  "job": {
    "id": "857ccca76cfe",
    "type": "site.lookup",
    "status": "done",
    "result": {
      "handler": "MY-cims.cidb.gov.my/w1",
      "version": "0123456789ab",
      "worker": "pc-office-1",
      "tookMs": 2400,
      "meta": { "task": "MY-cims.cidb.gov.my", "want": "w1", "tier": 2 },
      "result": {
        "status": "found",
        "reason": null,
        "records": [{ "name": "Gamuda" }],
        "source_url": "https://cims.cidb.gov.my/",
        "excerpt": "..."
      }
    },
    "error": null
  }
}

version is the first 12 hex characters of the handler file's SHA-256 hash. The hub sends the source with the job; the worker returns the handler's metadata and answer. couldnt_check and reason: "layout_changed" are normal handler results with job.status: "done". A thrown error, timeout or missing runner output instead produces job.status: "failed" and job.error.

HTTP statusMeaning
404Unknown handler id.
422Empty or overlong keyword, or a tier 3/4 handler. A non-runnable answer includes tier, tier4 (reason and evidence) and browser_steps.
400Invalid timeout or malformed JSON.

Poll with GET /api/lookup/{id}?wait=60; cancel with DELETE /api/lookup/{id}. An unknown job returns 404; cancelling an already finished job returns 409.

Why a site is tier 4 is in its tier4.evidence, with the date it was checked. Some Cloudflare sites challenge the handler's own reader (Node) but answer the worker's page reader: their evidence names the page to read with /api/fetch instead (rechecked 2026-11-07: bursamalaysia.com, mia.org.my, e-merger.mia.org.my).

At most one lookup per host runs across all workers, including different handlers on the same host. Other lookups for that host queue until completion, cancellation or lease expiry; different hosts can run in parallel. Workers must explicitly request site.lookup in their poll types. Google cooldown does not block lookups.

Handler library and health

GET/api/handlers?country=MY&host=cims.cidb.gov.my

Returns { "handlers": [...] } with index entries and no source text. Both filters are optional and match exactly. Every entry includes:

"health": {
  "state": "unknown",
  "last_ok": null,
  "last_fail": null,
  "last_reason": null,
  "broken_reason": null,
  "checked_at": null
}

States are unknown, ok and broken; timestamps are ISO strings once checked. Every finished lookup updates health: found or not_found (and, for a pdf handler, reason: "pdf") sets last_ok and moves unknown to ok; a failed job, couldnt_check or invalid answer sets last_fail and last_reason but does not change the state, since one slow or refused page is not a broken handler. layout_changed marks it broken immediately. Only a passing canary check turns a broken handler back to ok. last_reason belongs to the latest result; broken_reason keeps why the handler broke until it is ok again.

Canary checks

POST/api/handlers/check

{ "handler": "MY-cims.cidb.gov.my/w1" }

Omit handler (send {}) to check every runnable handler. Returns 202 with { "run": ... } and queues the two saved company names, canary.found and canary.not_found, for each handler. These jobs may wait up to 24 hours in the queue behind the per-host rule. A second check while one is running returns 409; an unknown id returns 404, and a tier 3/4 id returns 422.

A handler passes only when the positive company returns found with at least one record and the negative company returns not_found. Otherwise it is broken, with a reason naming the failed side. A pdf handler's job ends at the PDF address (read it with web.fetch), so it passes when both sides return reason: "pdf"; the check cannot see inside the PDF.

When a caller's lookup and canary lookups wait for the same host, the caller's goes first.

GET/api/handlers/check

Returns the last run, or { "run": null } before the first check. A run has id, started, finished (null while running), counts: { ok, broken, pending }, and handlers containing each handler's verdict, reason, and both sides' job ids and outcomes.

The hub starts a check 60 seconds after it starts (HANDLER_CHECK_START_DELAY_MS), then every 24 hours by default, skipping a tick while a check is still running. Set HANDLER_CHECK_INTERVAL_MS to change the interval, or 0 to disable both. Tests disable this timer. The library comes from HANDLERS_DIR (default <repo>/handlers); a missing library loads as zero handlers. Health and check runs are held in memory and cleared on redeploy.

Chat with web ChatGPT

POST/api/chat

Routes prompts to an active web ChatGPT session in a worker PC's browser (via the Local Worker Chrome extension), captures the live generated answer, and returns it as an API response. Every prompt opens its own new, unpersonalized temporary chat: it does not see earlier prompts, the account's memory or its custom instructions, and it is not saved to the account's history. The model is ChatGPT's default and cannot be chosen. If the tab cannot leave an old chat, the job fails with a "send the prompt again" message while the tab reloads.

curl -X POST https://YOUR-SERVICE/api/chat \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"callerId":"office-pc","taskDescription":"API request","prompt":"Malaysia Top News today","wait":60}'
FieldMeaning
promptThe question or prompt to send to ChatGPT. Required.
waitSeconds to hold the request open for the result, up to 900. Default: timeout plus 30 s. 0 returns 202 at once.
timeoutMsJob deadline, 10000 to 600000. Default 180000 (3 minutes).
workerPin the job to one worker by name.

200 with { "job": { "status": "done", "result": { "answer": "...", "tookMs": ... } } } when finished within wait.

Ads research

POST/api/ads

Who advertises in one country and industry, read from Google's Ads Transparency Center and Meta's Ad Library by a worker PC on its own line. Google needs no browser; Meta's Ad Library is opened in the PC's Edge or Chrome, headless. A search takes about a minute. The result lists every advertiser found, joined across both libraries by name or website.

curl -X POST https://YOUR-SERVICE/api/ads   -H "Authorization: Bearer $API_KEY"   -H "Content-Type: application/json"   -d '{"callerId":"office-pc","taskDescription":"API request","country":"Malaysia","industry":"solar","wait":300}'
FieldMeaning
countryA country name or 2-letter ISO code (Malaysia, MY). Required. 400 when it is neither.
industryThe industry, in a word or two. Required. The service turns it into the words searched: the industry itself, its usual synonyms (solar adds solar panel, solar installation, photovoltaic and, for Malaysia, tenaga suria), and for Google the country's company ending (solar sdn bhd). The words used come back in terms.
termsExtra words to search, up to 10.
maxMetaAdsMeta ads to read, 10 to 500, shared across the first three words. Default 150.
maxGoogleAdvertisersGoogle advertisers to read ads for, 1 to 100. Default 30.
activeOnlyMeta ads running now only. Default true.
googleRegionGoogle's region id (2000 plus the ISO 3166 number) for a country the service has no id for.
waitSeconds to hold the request open, up to 900. Default: timeout plus 60 s. 0 returns 202 at once.
timeoutMsJob deadline, 60000 to 1800000. Default 600000. Whatever was read by the deadline is returned.

200 with { "job": { "status": "done", "result": ... } }. The result has summary, notes, advertisers (both libraries joined; platforms, googleAds, metaAds, websites), google.advertisers (ads shown in the country, formats, first and last shown, preview images) and meta.advertisers (ads seen, how long the longest has run, formats, platforms, calls to action, the three longest-running ads with their text and link).

A search that goes wrong is labelled, not dropped. google.status and meta.status are ok, partial, empty, rate-limited, failed or no-browser (the PC has no Edge or Chrome, so only Google is read), and notes says why. Meta's keyword search also returns ads that only mention the word, such as a marketplace listing a solar lamp: those advertisers stay in the list with relevance: "unconfirmed" and sort below the ones whose name or ad text is about the industry. Google answers HTTP 429 to a line that asks too often; the worker waits twice, then stops asking and returns Meta's side with google.status: "rate-limited". Run the search again later.

Get, cancel and list jobs

GET/api/scan/{id}?wait=60

/api/jobs/{id}, /api/fetch/{id}, /api/shot/{id}, /api/audit/{id}, /api/lookup/{id}, /api/chat/{id} and /api/ads/{id} also retrieve jobs.

Returns the job. wait holds the request until it finishes, up to 900 seconds. 404 for an unknown id.

DELETE/api/scan/{id}

Cancels the job. /api/jobs/{id}, /api/fetch/{id}, /api/shot/{id}, /api/audit/{id}, /api/lookup/{id}, /api/chat/{id} and /api/ads/{id} also accept DELETE. 409 if it has already finished.

GET/api/scans?status=running

Recent jobs, up to 200, without results. status is optional: pending, running, done or failed. type is optional: gmap.scan, web.fetch, web.shot, site.audit, site.lookup, chat.ask or ads.research.

Behaviour

  • No worker free. A job waits in the queue. A scan fails after 30 minutes with no worker, a fetch, shot, audit or lookup after its timeoutMs.
  • Lost worker. A job whose worker stops responding goes back to the queue. After 3 lost workers it fails.
  • Google refusal. The worker posts what it has and rests for 30 minutes. The service sends it no scans meanwhile; it still takes fetches.
  • Restart. The queue is held in memory. A redeploy drops pending jobs. A job already running is re-filed when its worker posts the result.

Example: a complete round trip

# 1. start the scan, waiting up to 10 minutes
curl -X POST https://YOUR-SERVICE/api/scan \
  -H "Authorization: Bearer $API_KEY" -H "Content-Type: application/json" \
  -d '{"callerId":"office-pc","taskDescription":"API request","keyword":"factory","place":"Taman Daya","max":200,"wait":600}'

# 2. if the answer was 202, poll until it finishes
curl -H "Authorization: Bearer $API_KEY" \
  "https://YOUR-SERVICE/api/scan/<id>?wait=60"
